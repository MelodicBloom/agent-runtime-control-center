# 05 — Permissions and Approval

## Global rules

1. Never push to main.
2. Always create a branch for code changes.
3. Prefer draft PRs.
4. Always run build before claiming success.
5. Always report commands run.
6. Always report files changed.
7. Always include risk level.
8. Never edit secrets.
9. Never deploy production without approval.
10. Never delete large folders without approval.
11. Preserve project aesthetic DNA.
12. Keep phone summaries listenable.
13. Avoid giant code blocks unless requested.
14. Every recommendation should include why.
15. Every important decision should record alternatives.
16. Every unresolved question should remain visible.

## Risk levels

Low risk: read files, inspect repo, run checks, summarize.

Medium risk: edit files, create branch, commit to branch, open draft PR.

High risk: delete files, deploy, change env vars, modify auth, change billing, publish public pages.
